claude-sonnet-5 升级到 claude-sonnet-5-5 后报 400：先查 thinking、tool_choice 和 computer 工具

把代码里的 claude-sonnet-5 直接换成 claude-sonnet-5-5 后，如果请求一发出就返回 400，先看三处：thinking 是不是写了 disabled，tool_choice 是不是 any 或 tool，计算机使用工具是不是 computer_20251124。Anthropic 官方模型页已把 Claude Sonnet 5 标为旧版（Legacy），并在 Claude Sonnet 5.5 迁移指南里单独列出了从 Claude Sonnet 5 迁移要改的地方。本页按这份指南整理每种 400 的原因、改法和改完后的验证步骤。

为什么 claude-sonnet-5 的请求换成 claude-sonnet-5-5 会报 400？

Anthropic 官方 Claude Sonnet 5 模型页写明：Claude Sonnet 5 于 2026 年 6 月 30 日发布，目前状态为旧版但仍可用（Active, legacy），退役时间不早于 2027 年 6 月 30 日，官方建议考虑迁移到 Claude Sonnet 5.5。所以不升级也能继续调用 claude-sonnet-5，升级是可选的，但升级时不能只改模型名。

Claude Sonnet 5.5 迁移指南列出了五类在 claude-sonnet-5-5 上返回 400 的设置：thinking 预算（budget_tokens）、采样参数（temperature、top_p、top_k）、assistant 预填充、强制工具调用（tool_choice 为 any 或 tool）、thinking 设为 disabled。其中采样参数和预填充在 Claude Sonnet 5 上本来就会返回 400（Sonnet 5 模型页和迁移指南均有说明）；按官方模型总览，budget_tokens 这种手动思考模式在 4.6 之后的模型上也不再接受。因此，原来在 claude-sonnet-5 上能正常运行的代码，升级时需要新改的主要是 thinking disabled 和强制 tool_choice 这两类。

另外两处也会报 400：在 Claude API 上用 computer_20251124 版本的计算机使用工具，以及在 advisor 工具里把 Claude Sonnet 5 当作顾问模型。下面逐条说明。

官方资料：Claude Sonnet 5 模型页 https://platform.claude.com/docs/en/models/sonnet-5/overview ，Claude Sonnet 5.5 迁移指南 https://platform.claude.com/docs/en/models/sonnet-5-5/migration-guide 。

thinking 写了 disabled 报 400：改成 between_tools

Claude Sonnet 5 关闭思考的写法是 thinking: {"type": "disabled"}。迁移指南说明，Claude Sonnet 5.5 只接受 adaptive 和 between_tools 两种 thinking 类型，发送 disabled 会返回 400 invalid_request_error，报错信息会提示改用 {"type": "between_tools"}。

between_tools 是 Claude Sonnet 5.5 上最低的思考设置：模型回答前不先思考，但在多次工具调用之间写的简短进度说明会以 thinking 块返回；不带工具时，响应里只有文本。

改成 between_tools 时有三点限制，都会返回 400：一是 effort 只能是 low、medium 或 high，用 xhigh 或 max 会报错，要用这两档就去掉 thinking 字段或写 {"type": "adaptive"}；二是 between_tools 不能再带 display、budget_tokens 或 block_binding 等其他字段；三是用 between_tools 时，单条消息里的 output_config.effort 如果和当前生效的档位不同会报错，想每轮调整 effort 要用 adaptive。

官方给出的改写示例：原来 claude-sonnet-5 的请求写 thinking disabled 加 effort xhigh，改到 claude-sonnet-5-5 时写 thinking between_tools 加 output_config 里的 effort high。

tool_choice 是 any 或 tool 报 400：改成 auto 加 strict 工具

迁移指南写明，迁移页列出的更早模型都接受 tool_choice 为 any 或 tool，但 Claude Sonnet 5.5 对这两种都返回 400，token 计数接口也一样。报错信息是：tool_choice: type "tool" and "any" are not supported for this model.

官方给的改法：把 tool_choice 改成 {"type": "auto"}，并在需要的工具定义里加 strict: true，让工具入参符合 input_schema。改成 auto 后模型可以不调用工具直接回答，所以要在提示词里写清什么时候必须用这个工具，官方示例就是在用户消息里加上「Use the get_weather tool」。

使用 strict 工具时注意：严格模式只支持 JSON Schema 的一部分，每个 object 都要写 additionalProperties: false；一个请求最多 20 个 strict 工具；MCP、计算机使用和浏览器使用这几类工具集条目不接受 strict。工具多的时候只给真正需要的工具加 strict。

官方资料：strict 工具说明 https://platform.claude.com/docs/en/agents-and-tools/tool-use/strict-tool-use 。

计算机使用和 advisor 工具报 400 怎么改？

计算机使用：迁移指南说明，在 Claude API 和 Claude Models on Google Cloud（Google 托管）上，Claude Sonnet 5.5 只能通过 computer_toolset_20260801 工具集使用计算机，Claude Sonnet 5 常用的 computer_20251124 在这两个平台会返回 400；Amazon Bedrock 上仍然发送 computer_20251124。computer_20250124 在任何平台都不被 Claude Sonnet 5.5 接受。

如果原来的请求带了 fine-grained-tool-streaming-2025-05-14 这个 beta 请求头，换成工具集时要去掉它，它和工具集条目同时出现会返回 400；需要流式工具入参的工具改为单独设置 eager_input_streaming: true。

advisor 工具：以 Claude Sonnet 5.5 作为执行模型时，顾问模型只能是 Claude Opus 5、Claude Opus 5.5、Claude Sonnet 5.5、Claude Fable 5、Claude Fable 5.1、Claude Mythos 5 或 Claude Mythos 5.1。原来用 Claude Sonnet 5 当顾问的配置会返回 400。另外，Claude Sonnet 5.5 收到的顾问建议是加密的 advisor_redacted_result 块，响应里读不到建议原文。

不报错但结果变了：升级后还要检查的地方

对话只追加、不改写：迁移指南说明，Claude Sonnet 5.5 的每个 thinking 块都对它之前的对话做了签名；对 2026 年 8 月 31 日 00:00 UTC 及之后创建的账户，修改了前面的历史后再回传这些 thinking 块会返回 400。要改指令或工具，官方建议用对话中途的 system 消息。thinking 块还要原样回传，包括空的块。

工具调用之间的文字变成 thinking 块：Claude Sonnet 5 在工具调用之间写的文字都以 text 块返回；Claude Sonnet 5.5 上超过一两句的说明会以 thinking 块返回，默认 display 下内容为空。请求不会失败，但界面上原来显示的进度说明可能就没了。需要显示的话，adaptive 模式下可把 display 设为 summarized，或使用 beta 的 updates。

拒答类别更多：Claude Sonnet 5.5 拒答的类别比 Claude Sonnet 5 多，拒答时 stop_reason 为 refusal，stop_details 可能给出 cyber、bio、frontier_llm、reasoning_extraction、general_harms 等类别，代码里要处理这种结束原因。

其他变化：提示缓存的最小长度从 Claude Sonnet 5 的 1024 token 降到 512 token；effort 有 low、medium、high、xhigh、max 五档，API 默认 high，但各档位重新校准过，同一档位的思考量和 Claude Sonnet 5 不同，官方建议重新测一遍 effort 并重新评估成本。两个模型的价格差异以官网价格页为准。

改完后怎么验证？

第一步，发一个最小请求：model 写 claude-sonnet-5-5，带 max_tokens 和 output_config.effort，不写 temperature、top_p、top_k，不写预填充，不写 thinking disabled。返回 200 即说明模型名和基础参数没问题。读取结果时按 content 里每个块的 type 取 text，不要直接读 content[0].text，因为响应可能以 thinking 块开头。

第二步，逐个放回业务里用到的设置：需要关闭前置思考的加 between_tools，需要调工具的用 tool_choice auto 加 strict 工具，用计算机使用的换成 computer_toolset_20260801。每加一项都确认仍返回 200，并检查工具调用的入参是否符合 schema。

第三步，如果还返回 400，直接看响应体里的错误信息，对照本页各节：提到 between_tools 的是 thinking 设置问题，提到 tool_choice 的是强制工具调用问题，请求里有计算机使用工具或 fine-grained-tool-streaming 请求头的，对照计算机使用一节检查工具版本。官方迁移指南还提供了 Claude Code 自带的 Claude API 技能，可以用 /claude-api migrate this project to claude-sonnet-5-5 让它批量改代码，改完后再按清单人工核对。

通过中转调用时：本平台价格接口显示 claude-sonnet-5 和 claude-sonnet-5-5 都在售，端点类型包含 anthropic 和 openai。以上参数都按 Anthropic Messages 协议的写法说明，thinking、tool_choice、output_config 等字段在中转链路上是否原样转发，以实际返回为准；改完先用小请求确认，再切换正式流量。
