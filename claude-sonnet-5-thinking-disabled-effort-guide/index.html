claude-sonnet-5 的思考与 effort 设置：关闭写法、400 报错与 max_tokens

Claude Sonnet 5（模型 ID claude-sonnet-5）和 Claude Sonnet 4.6 有一个容易忽略的差别：请求里不写 thinking 字段时，它默认就开启自适应思考，而同样的请求在 Sonnet 4.6 上是不思考的。从旧模型迁过来的代码因此常遇到三类问题：沿用 budget_tokens 的请求返回 400；思考占掉 max_tokens，回答被截断；响应开头多出内容为空的 thinking 块。本页只依据 Anthropic 官方的思考文档、思考故障排查页、Effort 文档和 Sonnet 5 提示指南，说明各种 thinking 写法在 claude-sonnet-5 上的结果、怎样关闭思考、effort 怎么选和 max_tokens 怎么留。从 claude-sonnet-5 换到 claude-sonnet-5-5 后报 400 的情况，请看本站的 400 报错修复页。

先确认：不写 thinking 时 claude-sonnet-5 默认就在思考

Anthropic 的 Sonnet 5 提示指南写明：在 Claude Sonnet 5 上自适应思考默认开启，不带 thinking 字段的请求按自适应思考运行，这和 Claude Sonnet 4.6 不同，同样的请求在 Sonnet 4.6 上不思考。2026 年 6 月 30 日的官方发布说明也把它列为迁移到 Claude Sonnet 5 时的三项行为变化之一，另外两项是手动扩展思考（budget_tokens）被移除、设置采样参数会返回 400。

思考开启后，响应的 content 里可能先出现 thinking 块，再出现 text 块。官方文档说明，Claude Sonnet 5 上 display 的默认值是 omitted，thinking 块里的 thinking 字段是空字符串，只有 signature 字段有内容。这是正常情况，不是请求出错；读取回答时要按块的 type 取 text 块，不要直接读 content[0].text。

官方故障排查页还说明，自适应模式下模型判断问题足够简单时会跳过思考，所以有的轮次没有 thinking 块也属正常。想让它更常思考或想得更深，先调高 effort。

如果需要看到思考摘要，可以写 thinking: {"type": "adaptive", "display": "summarized"}。官方说明这里返回的是思考过程的摘要，不是原始思维链；无论 display 怎么设，thinking 块的计费方式相同。

thinking 各种写法在 claude-sonnet-5 上会怎样

官方思考文档按模型列出了每种 thinking 值的结果。Claude Sonnet 5 这一行是：不写 thinking 字段，按自适应思考运行；写 {"type": "adaptive"}，同样是自适应思考；写 {"type": "enabled"} 加 budget_tokens，返回 400；写 {"type": "between_tools"}，返回 400；写 {"type": "disabled"}，关闭思考。

budget_tokens 报 400 时，官方给出的报错原文是："thinking.type.enabled" is not supported for this model. Use "thinking.type.adaptive" and "output_config.effort" to control thinking behavior. 原因是手动扩展思考在 Sonnet 4.6 上已被标为弃用，在 Claude Sonnet 5 上被移除。改法是把 thinking 改成 {"type": "adaptive"} 或直接删掉 thinking 字段，用 output_config.effort 控制思考深度，不再写 budget_tokens。

between_tools 报 400 时，报错原文是："thinking.type.between_tools" is not supported for this model. 官方说明只有 Claude Sonnet 5.5 接受 between_tools，它在 Sonnet 5.5 上用来代替 disabled。如果代码同时给 Sonnet 5 和 Sonnet 5.5 发请求，要按模型分别写：Sonnet 5 关闭思考用 disabled，Sonnet 5.5 用 between_tools。

不想在代码里写死这张表，可以先查 Models API。官方 2026 年 10 月 5 日的发布说明写明，Models API 新增了 capabilities.thinking.types.disabled，10 月 15 日又新增了 capabilities.thinking.types.between_tools，分别表示模型是否接受这两种写法。发请求前读取 capabilities.thinking.types.disabled.supported 和 capabilities.thinking.types.between_tools.supported 即可判断。

要关掉思考怎么写，关之前先想清楚

关闭写法是在请求里加 thinking: {"type": "disabled"}。注意不要和 display 一起写，官方说明 display 不能与 disabled 同时使用，因为关闭后没有思考内容可以显示。

关闭前先确认目的。如果只是不想让思考文字出现在响应里，什么都不用改：Claude Sonnet 5 默认 display 为 omitted，思考文字本来就不返回。如果是嫌思考太频繁、延迟太高，官方提示指南的建议是：原来在 Sonnet 4.6 上不开思考的业务，到 Claude Sonnet 5 上先试试保留思考、调低 effort。

官方提示指南还提到两点。第一，大型或复杂的系统提示可能让模型更频繁地思考，可以在提示词里加引导，官方示例的意思是：思考会增加延迟，只在多步推理等能明显提高回答质量的问题上使用，拿不准时直接回答；改完要测量对效果的影响。第二，关闭思考后，模型更不容易主动调用工具或考虑搜索，如果业务依赖关闭思考时的工具调用，要在系统提示里明确写出什么情况下使用哪个工具。

官方表格里，Claude Opus 5 和 Claude Haiku 5.5 的 disabled 只在 effort 为 high 及以下时接受，Claude Sonnet 5 这一行没有这条标注。如果关闭思考后仍收到 400，以响应体里的报错信息为准逐项核对。

effort 五档怎么选

effort 写在请求的 output_config.effort 里，可选 low、medium、high、xhigh、max 五档。Claude Sonnet 5 在 Claude API 和 Claude Code 上默认 high；官方说明把 effort 显式设成默认值，与不传这个参数的行为完全相同。adaptive 是思考模式，不是 effort 档位，不要把 adaptive 填进 effort。

官方对各档的建议：max 是不限 token 花费的最高能力；xhigh 适合最难的编码和智能体任务；high 是默认值，适合大多数用途；medium 适合需要降低 token 用量、可以接受一定能力损失的成本敏感场景；low 留给范围明确的短任务和对延迟敏感、对智能要求不高的场景。

从 Sonnet 4.6 迁移时，官方给了一个粗略对应：Claude Sonnet 5 的 medium 在智能上约等于 Sonnet 4.6 的 high，Sonnet 5 的 high 约等于 Sonnet 4.6 的 max；做评测时要按实际观察到的思考长度对齐，而不是按档位名称对齐。

官方还说明 Claude Sonnet 5 严格遵守 effort，尤其在低档：low 和 medium 下它只做被要求的事，中等复杂的任务在 low 下有思考不足的风险。遇到复杂问题推理太浅，官方建议先把 effort 调到 high 或 xhigh，而不是靠提示词绕；必须保持 low 时，可以在提示词里加一句提示，说明这个任务需要多步推理、要先仔细思考再回答。

max_tokens 要留足：回答只剩一半、stop_reason 是 max_tokens

官方说明 max_tokens 是总输出的硬上限，思考和回答文字都算在里面，即使思考文字没有返回也照样占用。思考较长时，可能出现响应几乎全是思考、回答被截断、stop_reason 为 max_tokens 的情况。

官方提示指南特别提醒两点：一是在 Sonnet 4.6 上不开思考的业务，迁到 Claude Sonnet 5 后要重新检查 max_tokens；二是 Claude Sonnet 5 使用新的分词器，同样的文本大约多出 30% 的 token，具体增幅取决于内容，所以按 Sonnet 4.6 调好的 max_tokens 可能截断同样长度的输出。

解决办法是调高 max_tokens，或把 effort 降到 medium。在 high、xhigh、max 档运行时，官方建议给 max_tokens 留出思考和工具调用的余量。Claude Sonnet 5 同步 Messages API 的最大输出是 128K token；在 Message Batches API 上带 output-300k-2026-03-24 beta 请求头时可到 300K。

排查时先看响应的 stop_reason：是 max_tokens 就说明额度被用完，调高 max_tokens 后重试；是 end_turn 但回答比预期短，官方提示指南说明 Claude Sonnet 5 会按任务复杂度调整回答长度，需要更详细的回答时在提示词里写明。

temperature、top_p、top_k 也会报 400

Claude Sonnet 5 模型页写明，设置 temperature、top_p 或 top_k 会返回 400；6 月 30 日发布说明的表述是把这些采样参数设为非默认值时返回 400。官方提示指南说明这是 Sonnet 系列新增的限制，迁移时应删除这些参数。

claude-sonnet-5 的请求返回 400 时，先检查实际发出的请求体里有没有这三个字段，包括所用框架或客户端的设置里是否还留着温度等采样参数。

原来靠 temperature 控制风格多样性的，官方建议改用系统提示词说明语气和变化要求；需要每次产生明显不同的方案时，官方的做法是先让模型列出几种不同方向，由用户选定一种再实现。

多轮对话里：改 effort 会让缓存失效，思考块要原样回传

官方 Effort 文档说明，对话中途按消息切换 effort 的 beta 功能只支持 Claude Fable 5.1、Claude Mythos 5.1、Claude Opus 5.5、Claude Opus 5、Claude Sonnet 5.5 和 Claude Haiku 5.5，不包括 Claude Sonnet 5。在 Claude Sonnet 5 上换档只能在下一次请求里改顶层的 output_config.effort，提示缓存会从头开始。

官方故障排查页还说明，思考设置和 effort 档位都属于缓存前缀的一部分，切换思考模式、改 effort 都会让缓存断点失效，表现为 cache_read_input_tokens 降到 0。同一段对话里应保持思考设置和 effort 不变；把参数显式写成默认值与不写等价，不会让缓存失效。

带工具的多轮对话要把上一轮 assistant 消息原样回传，包括 thinking 和 redacted_thinking 块，即使 thinking 字段是空的。如果代码按类型过滤内容块、丢掉了 redacted_thinking，或者重新拼装了 assistant 消息，会收到 400，报错信息包含：`thinking` or `redacted_thinking` blocks in the latest assistant message cannot be modified。改法是不做过滤，直接回传 API 返回的内容。

通过中转调用时的验证方法

本页的参数名、默认值和报错原文来自 Anthropic 官方文档，按 Anthropic Messages 协议的写法说明。本平台价格接口显示 claude-sonnet-5 在售，端点类型包含 anthropic 和 openai；请求地址、认证方式以平台接口文档为准。中转层是否原样转发 thinking、output_config 等字段，官方文档没有说明，需要自己用小请求确认。

建议按这个顺序验证。第一，不写 thinking、不写 temperature，发一个带 max_tokens 的最小请求，确认返回 200，并按块类型取到 text 块。第二，加上 thinking: {"type": "disabled"} 再发一次，确认返回 200 且响应里没有 thinking 块；再改成 {"type": "adaptive", "display": "summarized"}，在需要推理的问题上应能看到带摘要文字的 thinking 块（简单问题可能直接跳过思考）。第三，用同一个提示分别以 low、medium、high 各发一次，比较响应 usage 里的输出 token 数和耗时，几档之间几乎没有差别时，再确认 effort 字段是否传到了上游。

最后在自己的长任务上检查 stop_reason 不是 max_tokens。选定档位和思考设置后在代码里显式写出来，避免以后默认值变化带来意外。费用以官网价格页为准。
