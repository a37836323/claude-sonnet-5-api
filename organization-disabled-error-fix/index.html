this organization has been disabled 到底表示账号问题还是请求问题？

从错误原文看，应优先将其视为 organization 状态相关问题，而不是单个请求内容不合法，也不能直接等同于 401 Unauthorized、429 或某种额度耗尽。仅靠这条文本，无法判定禁用的具体原因。

可把问题分成三层：账号或 organization 层、请求层、额度层。若同一身份下，替换输入内容、缩短任务、换新会话后仍返回完全相同的 organization disabled 文本，账号层的可能性上升；但最终原因仍需由对应账号侧状态确认。

不要把 HTTP 400 自动解释为 JSON 格式、字段名或模型名出错。状态码表达的是服务端对本次请求的处理结果，具体语义应以响应 body 中的错误文本为准。

如何按优先级排查 Cline 的 api error？

再检查 Cline 或启动脚本是否把旧变量覆盖了新变量。可复制执行：printenv | sort | grep -Ei 'api|key|token|base|url'。如果通过 shell 配置加载变量，再执行：grep -nEi 'api|key|token|base|url' ~/.zshrc ~/.bashrc ~/.profile 2>/dev/null；该命令只帮助定位本地配置，不会判断远端账号状态。
